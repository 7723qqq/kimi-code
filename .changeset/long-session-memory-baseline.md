Add a long-session memory growth regression baseline (`long-session-memory.test.ts`, gated on `KIMI_E2E=1`). Runs `TURN_COUNT = 20` consecutive native-LLM turns through the Rust engine via `createRunTurnOverride`, each driving a single Read tool call against a pre-seeded workspace. After every turn samples `process.memoryUsage().{rss, heapUsed, external}` and per-turn elapsed wall-clock so future regressions in the engine or its host bridge surface as monotonic growth. The collected samples are the project's first baseline for this scenario; the first commit deliberately does not assert a hard threshold (a tighter bound can be wired in once we have multiple data points to compare against). Sample run on this fork (minimax anthropic `MiniMax-M2.7`, 20 turns, 51s total): RSS settles to 280–281 MB after V8 GC of the initial LLM SSE buffer (turns 1–2 are 361.5 MB, turns 3–20 stay within 1 MB), heap delta is −36 MB over the run, per-turn elapsed median 2568 ms with min/max 2232/3086 ms. Also adds `long-session-memory.test.ts` to the package's `vitest.config.ts` include list and prefers anthropic providers in `pickAnyProvider` so the test does not pick a free-tier default that the provider marks as unavailable.
