Classify native-stream failures like provider errors, and stop leaking abort listeners (a25/F2, a25/F5 of the 2026-10-12 audit).

**A native API failure is classified instead of killing the step** (`kosong`, a25/F2). The Rust pipeline reports HTTP failures as `API error (<status>): <body>`, but both native delivery paths threw a bare `Error` from inside the consumer's iteration — i.e. *after* the provider's `try/catch` around `tryNativeLlmStream*` had already returned, so no `convert*Error` ever saw it. The status was therefore dropped on the floor: a transient 429 reached `isRetryableGenerateError` as a plain `Error` (not retryable) and the step died on the first blip, while a quota-exhausted 429 bypassed `classifyKimiQuotaError` (which reads a `status` property). Both paths now throw `NativeLlmApiError`, which carries the parsed status, and each provider's error converter classifies it with the same rule and vendor hook its SDK errors get. A failure with no HTTP status (connection reset, idle timeout) is treated as a 5xx and stays retryable. Deliberately not a kosong `APIStatusError`: `native-stream.ts` is provider-agnostic and must not decide which provider class a status maps to. Behaviour note for the native path only: a 4xx now fails fast instead of being retried.

**Gemini requests no longer accumulate abort listeners** (`kosong`, a25/F5). `abortPromise` registered a `{once: true}` `abort` listener and relied on it firing to be removed — but on the normal path the SDK request wins the race, so nothing ever removed it. A session-level signal handed to every `generate()` of a turn therefore collected one listener per call, and Node started warning (`MaxListenersExceededWarning`, default ceiling 10) from the 11th call on, burying real signal problems in noise. The race is now a cancelable `raceWithAbort` that removes its listener in a `finally`, and the abort semantics are unchanged (an already-aborted signal still fails before the request; abort still wins over a pending request).
