Close two silent-failure holes on the Rust native boundary (a38/F1, a38/F2 of the 2026-10-12 audit).

**A knowledge search can no longer report "nothing matches" when it actually failed** (`kimi-native-tools`, `agent-core-v2`). An FTS5 query was passed through raw whenever it contained a `"`, so an unbalanced quote (`foo "bar` — natural language carries quotes) was a MATCH syntax error. FTS5 reports that failure on the *first row* of the iterator, and the reader dropped per-row errors with `.flatten()`, so the search returned an empty set: the model was told "No matching knowledge entries found." for an entry that existed. Queries now go through one `escape_fts_query()` (every term phrase-quoted, quotes doubled, terms OR-ed) and the FTS5/scope/tag readers propagate both `query_map` and per-row errors as `knowledge search failed: …`. `knowledgeService.search` no longer swallows that error either, so a failed search reaches the caller instead of masquerading as an empty library; `[]` now means only "nothing matches". The escape removes the natural-language failures but cannot make every input parseable (a query with no searchable term still builds an empty MATCH expression), which is exactly why the error must surface rather than be folded into an empty result.

**`timeout_ms` is an idle deadline, not a wall-clock budget for the answer** (`kimi-native-tools`, `kosong`). `reqwest::Client::timeout` covered connect + request + full body, so the callers' hardcoded 120 s cut off a healthy slow stream mid-answer: long reasoning, large streamed tool arguments or a slow gateway ended the turn after two minutes — and the buffered path re-issued the same request on the fallback, while the incremental path failed after parts had already been dispatched into the transcript. The client now carries a separate 10 s `connect_timeout`, the overall request ceiling is `max(timeout_ms, 30 min)` (only guards a stream that never ends), and every `stream.next()` is wrapped in a `timeout(timeout_ms)` that resets on each SSE event — 120 s without a single event is a dead stream, an event every 60 s is a healthy one. The three provider call sites keep `120_000` and now say in place that it is the idle deadline. Behaviour change worth noting: a stream that stays silent is still cut off, but a stream that keeps producing is no longer truncated, so native circuit-breaker counts no longer treat long healthy streams as failures.
