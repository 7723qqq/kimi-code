Prompt governance: one owner per behavior rule, and delivery metadata for what each profile sends, omits, or defers.

**Who receives these edits.** `system.md` is rendered for every non-minimal family — that is every session except DeepSeek — so each sentence removed there is removed for all of them. `system.minimal.md` is rendered only for families declaring `promptShape: 'minimal'` (today DeepSeek), and the DeepSeek reminder replays what the minimal template used to carry.

- `behavior-contract`: the six working rules now have a single owner, `agentProfileCatalog/behaviorContract.ts`, exposed as stable ids (`authority_and_untrusted_content`, `act_and_verify`, `tools_and_repository_context`, `safety_and_scope`, `failure_and_partial_progress`, `communication`) with a `full` and a `minimal` rendering. `system.md` gained a `# Working contract` section that renders all six, and the sentences those clauses now own were deleted from the template so a rule is never stated twice: `# Risky actions` (reversibility and blast radius), "Do what was asked" under `# Delivering work`, the verification half of the `# Delivering work` paragraph, and the first two sentences of `# Tool use`. **What each deleted sentence enforced, and what enforces it now:** the escalation rule for hard-to-undo actions is `safety_and_scope` (now also naming secret-file reads and the permission policy as the enforcing layer); "do what was asked" plus the verify-before-done rule is `act_and_verify`; dedicated-tool-first and parallel calls are `tools_and_repository_context`. Nothing was dropped without a clause taking it over, and every clause is asserted by anchor in `test/app/agentProfileCatalog/profile-shared.test.ts`.

- `system.minimal.md`: rebuilt as persona + cwd + `${role_additional}` + the two core clauses + a stable handoff marker, "The remaining working rules follow in the model-adaptation reminder." The three v4.1 working rules that used to be copied here (full reasoning replay, call tools with the arguments as given, restate the objective on a long session) are unchanged in substance but no longer duplicated: they are delivered by the DeepSeek reminder, which is where the minimal shape already sends the other four clauses. **Loss named:** a minimal-profile session no longer reads those three rules in its system prompt, so a truncated or reordered context cannot drop them independently of the reminder; the reminder is registered per live context and re-injected once after compaction, which is the same durability the other four clauses already had. Non-DeepSeek models render byte-identical text to before (`leaves every other model on the shipped template, byte for byte`).

- `model-adaptations/curated/deepseek.md`: `renderCuratedAdaptation` now composes the reminder instead of returning the file verbatim — it prepends the four clauses the minimal shape delegates (from `renderDelegatedBehaviorContract()`), states that the guidance is authored for this repository, hand-written and not measured, and keeps the curated body under `## Working rules delegated by the minimal prompt`. No curated text was deleted, and `DeepSeekAdaptationService` is untouched: it still owns family gating, the in-flight cache, reminder registration and the one post-compaction reinjection.

- `render-result`: `SystemPromptRenderResult` gained three optional fields, so every existing caller compiles and no field changed meaning. `contractDelivery` reports each core id's channel — `system` for the full shape and the two template clauses of the minimal shape, `reminder` for the four delegated ones, `intentionally_omitted` with a reason when a minimal family has no reminder channel. `valueDelivery` classifies every non-empty variable the profile did not carry, with a reason, instead of leaving it to a `droppedVars` list that mixes "composed elsewhere" with "deliberately omitted". `warnings` reports an unresolved `${name}` as `unresolved_variable` — previously a placeholder that survived rendering looked like a clean render. `droppedVars` keeps its meaning and is still emitted when non-empty.

- `AGENTS.md` / `DEVELOP.md`: the repository's own instruction ownership moved to where it can be maintained. `AGENTS.md` keeps the entry pointer and now states that only it is injected while `DEVELOP.md`, `CONVENTIONS.md` and `CONTRIBUTING.md` are read on demand — no file claims `DEVELOP.md` is injected. `DEVELOP.md` gained `## Instruction Ownership and Precedence` and `## Prompt Assets and the Prompt Optimizer`, and `bun run check:prompt-ownership` fails when the pointer, the "read on demand" statement or a core id disappears.
