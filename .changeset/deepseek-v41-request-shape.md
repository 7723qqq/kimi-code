DeepSeek-V4.1 request shape: family output tiers, tool-constraint preemption, provider definition, gateway-qualified ids.

- `max_tokens`: when a caller sets no completion cap and the model belongs to the `deepseek` family, the request now carries the family tier instead of nothing — 8192 without thinking, 65536 with thinking, 131072 at `max` effort. The tier follows the effort that actually applies after `thinking` is normalized, so `effort: 'on'` takes the model's default tier and an always-thinking model never falls to the no-thinking tier. **User-visible change:** an unconfigured DeepSeek endpoint previously relied on its own default, and vLLM-style fronts often default far lower, truncating the answer with no client-side signal. An explicit caller cap still wins and is still clamped to the remaining context window; an explicit `0` still sends no cap at all, and once the remaining window is exhausted the request now carries no cap instead of being floored at one token — an overflow surfaces as the endpoint's own error rather than as a truncated answer reporting `finish_reason: 'length'`.
- `response_format`: with tools present on a DeepSeek model the field is dropped, because deepseek-recipe selects the tool-call grammar as the output constraint in that case and silently ignores the response format. The drop happens after `extraParams.openai` is merged, so a caller cannot reintroduce it through extra params.
- `provider`: a first-class `deepseek` provider definition (openai protocol, `DEEPSEEK_API_KEY` / `DEEPSEEK_BASE_URL`, default `https://api.deepseek.com`) carrying the family capability and its own connection. Definition lookup now tries the provider **id** before its `type`, so the documented `[providers.deepseek] type = "openai"` entry resolves to this definition for the endpoint, the credential and the capability. **User-visible change:** before this, only `type = "deepseek"` reached the definition — the documented shape resolved to the generic `openai` pair, so a request without `base_url` went to `api.openai.com` carrying `OPENAI_API_KEY`. A provider id that is not registered resolves exactly as before. Registration never overwrites an existing definition of the same id.
- `model-family`: identification now also matches a gateway-shaped id whose family segment is not the last one (`vendor/deepseek-proxy/foo`), while `my-deepseek-clone` still does not match.
- `prompt` — **who receives it.** Three edits, two audiences:
  - `system.minimal.md` gains a short working-rules block (full reasoning replay, call tools with the arguments as given, restate objective and constraints on a long session). Only families declaring `promptShape: 'minimal'` render this template, so today that means DeepSeek sessions; every other session is unaffected. This is the operative copy, because the minimal shape drops AGENTS.md, the skill and plugin sections, and the model-adaptation section.
  - `model-adaptations/curated/deepseek.md` gains the same three rules as `## Reasoning history`, `## Tool arguments` and `## Long context`. It reaches the same DeepSeek sessions through the reminder channel rather than the system prompt, so the two copies must stay identical in substance.
  - `system.md` gains one sentence under Tool use: tool arguments arrive structurally valid under the endpoint's constraint, so a call is emitted as given and repaired arguments are never re-emitted. This template is rendered by every non-minimal family, so **all non-DeepSeek sessions receive this sentence**.
- `docs`: `docs/en/llm.md` now owns the rationale that used to live in source comments — why `fallbackTokens` and `tokenCap` stay independent, the DeepSeek HTTP-400 reasoning-replay requirement, the ignored-sampling-parameter rule, the cache-split rejection rule, the `droppedVars` and composed-block bookkeeping, and the fence-aware `##` truncation of adaptation files. `docs/zh/llm.md` is a full translation of that page (it did not exist before, and the page had just grown). `docs/en/configuration/providers.md` and `docs/zh/configuration/providers.md` document `deepseek` as a provider id over the `openai` protocol, not as a new `type`.
- `comments`: `scripts/no-comments-baseline.txt` is empty and its header now states the scope — three packages (`agent-core-v2`, `kap-server`, `transcript`) under `src/`, `test/`, `scripts/`. The 157 comments it tolerated across 20 files (source and tests) were migrated into `docs/en/llm.md` and deleted; no entry was carried forward. Outside that scope the repository keeps its comments: `kosong`, `klient`, `node-sdk`, `telemetry`, the apps, and the root `scripts/` were audited for family/adaptation rationale and every remaining comment there was kept because it documents a local API or a command, with the design reasoning it used to duplicate now living in `docs/en/llm.md`.
- `token-counting`: the prompt token estimate now has a single `PromptTokenCounter` seam, whose default implementation is the estimator function itself, and compaction's overflow path takes the counter as an injectable argument. A committed baseline fixture records the estimator's real deviation on CJK prose (43% over), ASCII code (5% under) and JSON tool arguments (25% under) against a live DeepSeek endpoint, with per-category tolerances. A synchronous `TokenCounter` chain (`wasm → heuristic`) rejects a backend that fails to construct or counts nothing; `sidecar` and `http` backends are tier B only and refuse to run on the synchronous request path. No new runtime dependency.
- `determinism`: an optional `determinism` request option sends a stable integer `seed` derived from the model name and the first user message, overridable per call. `temperature` never survives on this family — it is in the family's ignored list and `stripIgnoredSamplingParams` removes it regardless of thinking mode — so the option does not claim to pin a temperature it cannot send.
- `tail-anchor`: `shouldReanchorTail` decides from the estimated context size whether a turn needs the objective and hard constraints restated near the end, and the `deepseek_tail_contract` reminder variant delivers it, idempotent while a previous injection is still in context and firing again after compaction drops it. `ContextInjectionContext` gained `estimatedTokens` so an injection can make a size decision.
