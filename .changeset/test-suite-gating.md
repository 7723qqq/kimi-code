Test-suite gating and platform-neutral assertions.

- `test:heavy` (new): the work that needs real processes, real sockets, or real git is no longer part of the default suite. Each package's `bunfig.toml` excludes it through `test.pathIgnorePatterns`; `KIMI_TEST_HEAVY=1` plus the runner's `--include-heavy` flag — wrapped as `bun run test:heavy` — puts it back, and the new `test-heavy` CI job runs that wrapper so the excluded files are not silently orphaned. Nothing was deleted: every excluded file still runs, just not on every default invocation.
- `minidb`: `test/e2e/**`, `test/cluster/**` and `bench-json.test.ts` are the heavy set. Measured on one Windows machine: 49 files / 562 tests / 226s of test time became 33 files / 496 tests / 27.5s.
- `agent-core-v2`, `apps/kimi-code`, `kap-server`, `acp-server`: `*.e2e.test.ts` and `test/e2e/**` moved to the heavy set. `acp-server`'s `test/e2e-turn.test.ts` is included by path because it does not carry the `.e2e` suffix but waits up to 10s per assertion.
- `agent-core-v2` real-I/O suites: four files that drive a subprocess per case joined the same heavy set — `test/features/tower/store.test.ts` (198 cases, 214s measured, one `git` spawn per assertion), `test/app/git/gitService.test.ts`, and `test/mcpCore/{connection-manager,client-stdio}.test.ts` (each case spawns a runtime and waits out a connection timeout). The tower suite's fixture stopped initializing a repository per case as well: one template repository is built once and copied, which takes five `git` spawns out of every case.
- `packages/kosong`, `packages/node-sdk`, `packages/oauth`: each gained a `test` script so `bun run test` works inside the package instead of only through the root project list.
- `hostFsService.test.ts`, `agentsMdReminder.test.ts`, `profile/context.test.ts`, `plugin/manifest.test.ts`, `sessionExport.test.ts`, `workspaceService.test.ts`: symlink behaviour is now gated on `test/_support/symlinkSupport.ts`, a probe that actually creates a link, because Windows refuses `symlink` without Developer Mode or elevation. Where links are supported the assertions run unchanged; where they are not, the group is skipped rather than failed. Ten assertions that failed for this reason now pass on Linux and skip on an unelevated Windows.
- `apply-profile.test.ts`, `fullCompaction.test.ts`, `binding.test.ts`: three assertions compare against a byte-for-byte golden system prompt that declares `os:Linux` and `shell:bash:/bin/bash`, and two more feed the host's own path into a runtime the harness deliberately simulates as Linux. Both fixtures describe a POSIX host, so those five are gated on `process.platform === 'linux'` instead of being made platform-agnostic — rewriting the golden would delete the regression it exists to catch (the prompt must not drift by a single character).
- `binding.test.ts`: four hand-built `ISessionAgentProfileCatalog` stubs were missing `inspect`, hidden from `tsc` by `as unknown as`. Production calls `catalog.inspect(...)` from `profile-shared.ts`, so three tests threw at runtime. The stubs now implement the method.
- `modelAdaptations.test.ts`, `prompt-optimizer`'s `model` and `smoke` tests: expectations are computed with `path.resolve`/`join`/`basename` instead of hard-coded POSIX literals, so the same assertions hold on both separator styles. No expectation was loosened.
- `features/tower/store.test.ts`: file content read back from a git worktree is normalized for CRLF, because `core.autocrlf` on Windows rewrites the `\n` the fixture wrote. The byte-for-byte comparison remains.
