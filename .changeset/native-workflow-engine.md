Add a native workflow engine to the Rust agent (ported from the retired `agent-core-v2` workflow domain). Workflow scripts run in an embedded QuickJS sandbox (`rquickjs`) as an async IIFE with the v2 primitives injected — `agent()`, `parallel()`, `pipeline()`, `phase()`, `log()`, `sleep()`, workspace-jailed `readFile`/`writeFile`/`glob`/`exists`, `fetch()`, `exec()`, `search()`, `args`, `console`, `URL` — and no Node API. The engine ships: a regex meta parser plus the nine built-in scripts (deep-research, code-review, test-generator, refactor-planner, bug-triage, pr-description, architecture-review, security-audit, migration-planner), an App-scoped run registry (`start`/`status`/`wait`/`cancel`/`list_builtins`, runs on a dedicated thread so non-`Send` QuickJS futures never touch the caller runtime), and a `SubagentWorkflowHost` adapter that turns `agent()` into a foreground subagent run. The `Workflow` tool is advertised in the main tool table and dispatched natively (`run`/`status`/`wait`/`cancel`/`list`); its registry is process-wide so a `run` started in one turn can be `wait`ed on in the next, and user workflows load from `<KIMI_CODE_HOME>/workflows/<name>.js`. The embedded engine is behind the `workflow-js` cargo feature (on by default): build with `--no-default-features --features napi` for a no-QuickJS, no-C-dependency binary where `run` reports the engine is unavailable while `list`/`status`/`cancel` keep working.
