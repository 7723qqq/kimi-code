Parallelize the Rust engine's native grep and converge its memory profile: directory traversal switches from a serial walk to the `ignore` crate's native `WalkParallel`; file scanning streams line-by-line through a `BufReader` instead of loading whole files (the 4MiB cap and NUL binary-skip contracts are preserved); content mode retains only the `-A`/`-B`/`-C` context window; a single `metadata()` call is reused per entry; the timeout budget becomes an atomic deadline flag. Output ordering follows a deterministic contract shared with the host — `files_with_matches` sorts by whole-second mtime descending with a path-ascending (code-unit order) tiebreak, and sorting happens before truncation; `content`/`count` use path-ascending order. The host `grepTool.ts` (agent-core-v2) is updated to the same contract: its tiebreak changes from rg's output order to path code-unit order, so engine and host produce identical ordering (verified equal across a 40-file same-second fixture). On the 2000-file benchmark the median drops from ~2820ms to ~26ms (~109x), now faster than host ripgrep (~38ms), with near-zero peak memory. No rayon; `Cargo.lock`/`flake.nix` untouched. Adds 4 parallel-semantics unit tests; all gates green (cargo test 908+18, clippy/fmt, vitest 119+9, contract 68, engine-zero-js-loop).
