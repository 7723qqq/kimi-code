DeepSeek-family specialization, layered on the model-family table rather than on ad-hoc branches.

- `usage`: the engine's own OpenAI-compatible `parseOpenAIUsage` (`human/llm/requester/bases/openai/format.ts`) now reads DeepSeek's top-level `prompt_cache_hit_tokens` / `prompt_cache_miss_tokens`, falling back to OpenAI's `cached_tokens` / `prompt_tokens_details.cached_tokens`. The DeepSeek shape wins when both are present, `prompt_cache_miss_tokens` is used verbatim instead of being recomputed, and `inputOther` is clamped to non-negative. Previously every cached prompt token was billed as full-price input — a response reporting 1792 hit / 219 miss was counted as 2011 full-price input. The same classification already existed in `packages/kosong`; it was missing from the v2 engine's copy.
- `thinking`: `encodeOpenAIThinkHistoryKwargs(model)` now takes the model name and reads the family's history default, and its fallback for every other model is `high` (previously `medium`). DeepSeek's declared history default is `high`.
- `prompt`: DeepSeek models now run a minimal system prompt, modeled on deepseek-harness's `minimal` agent preset (`packages/bundle/web-app/presets/minimal.patch.yml` — a one-sentence persona with `complete: true`). The DeepSeek system prompt is a single persona sentence plus one working-directory line; AGENTS.md, the skills/plugins sections, the model-adaptation section and per-subagent role text are no longer part of it. The curated `deepseek.md` adaptation therefore moves out of the system prompt into a per-agent reminder injection (`features/deepseekAdaptation`), delivered as a user-role `<system-reminder>` and re-injected when compaction drops it. Selection stays automatic on the `deepseek`/`xopdeepseek` family prefixes via `promptShape`.
- `tokens`: image token accounting implements the DeepSeek vision formula (14px patches, 3:1 downsampling, 544px scale-up floor, 1024-token cap, aspect-preserving grid solve iterated to a fixpoint). The formula is a derivation from the family constants calibrated against a live endpoint — not a reproduction of a published spec, and not exact. Measured against `workbuddy/deepseek-v4.1-flash` (image portion = `prompt_tokens` minus a text-only baseline), formula → measured: 200×200 169→185, 512×512 169→185, 1024×1024 625→653, 1024×512 338→341 (deltas +3…+28). Images that previously cost a flat 1024 estimate now price by size when dimensions are known, and fall back to the cap otherwise.
- `model-family`: the `deepseek` entry carries the reasoning-effort vocabulary (`none`/`low`/`high`/`max`, off value `none`, history default `high`), the image pricing, `promptShape: 'minimal'` and `curatedAdaptation: true`, and its prefixes now also cover the astron-hosted ids (`xopdeepseek*`). The declared vocabulary is a collapsed form of what the endpoint accepts rather than a mismatch: DeepSeek documents a many-to-one mapping (minimal→low, low→low, medium→high, high→high, xhigh→high, max→max), so several requested values resolve to the same actual effort. Only the history default is consumed today. The entry also declares `thinkingHistory`: `fullEchoWithTools` (see the `thinking` entry below) and the sampling parameters thinking mode silently ignores.
- `media`: image parts carry optional `dimensions` (populated from the read-media and compression paths) and an optional `detail` (forwarded to the wire when set). Dimensions stay client-side for pricing; neither field is sent unless present, so non-DeepSeek requests are unchanged. `lowDetailPx` was removed from the image pricing — the live endpoint prices 200×200 and 512×512 identically, so there is no low-detail tier.
- `kosong` (private, no separate entry): the OpenAI-Responses usage extractor now classifies DeepSeek's `prompt_cache_miss_tokens` as plain input (`inputOther`), matching the Chat Completions extractor, instead of as cache creation. The OpenAI-compatible provider's history auto-inject now pairs `reasoning_effort: high` (previously `medium`) when the history already carries thinking.
