Fix the tui2 skeleton's wiring against the v2 host: `apps/kimi-code/src/cli/run-shell.ts` now reads `tui.uiMode` (a getter exposed by both v1 and v2 `KimiTUI`) instead of `tui.state.ui.mode`, which didn't exist on the v2 host and broke typecheck. Inside `apps/kimi-code/src/tui2`, the tasks-browser controller now opens and closes the dialog through the same `activeDialog` slot the other controller-managed dialogs use, and the main shell renders it via `dialog() === 'tasks-browser'`. The store exposes a new `patch(key, partial)` helper that centralises every partial slice write with a spread, so SolidJS `createStore` setters stop wiping sibling fields (filter / selectedTaskId / tailOutput / viewer / flashMessage on tasks-browser, active / running / agentId on the BTW panel mid-stream, pendingApproval / pendingQuestion on `livePane` during mode toggles, parallel-command output cards in `shellOutputs`, and `supportsProgress` on `terminalState`). The store-level helper makes that invariant live in exactly one place; controllers delegate to it instead of repeating the spread at each call site. The flash banner's auto-clear timeout no longer uses object identity (which never survived the spread) and now reliably clears its own banner.
