# Format: `<path>:<endpoint> <count>`. An entry that stops matching is reported
# as stale, so this file cannot rot silently.
#
# Severity is deliberately inverted from intuition: a *missing* endpoint is only
# a `warn` because the call throws the first time it runs, which is loud and
# cheap. A *degraded* endpoint is an `error`, because it returns a plausible
# wrong answer and nothing ever tells you.
#
# Every entry in ENDPOINTS was verified by running the same probe under Node
# 24.9.0 and Bun 1.4.4 and diffing the results — not by reading a compatibility
# page. That process removed four claims a docs-only reading produced:
#   * `eventLoopUtilization()` returns all zeros under Node >= 23 as well;
#   * `executionAsyncId()`/`triggerAsyncId()` return 0 outside a hook in Node too;
#   * `tls.pskCallback`/`requestOCSP`/`SNICallback` are socket options, present
#     in neither runtime's module exports, so they are not gaps at all;
#   * `moveMessagePortToContext`, `takeCoverage`, `stopCoverage` and
#     `promiseHooks` all exist in Bun (the last three throw when called).
