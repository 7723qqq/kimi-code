# Package scripts nothing in the repository invokes.
#
# One entry per script: the `package.json` path, a colon, then the script name.
#
# A script here is one a maintainer types by hand. That is a legitimate shape —
# `bun run e2e`, the prompt benchmark, the native packaging steps — so absence
# from the call graph is not by itself a defect. Listing it records that someone
# looked and decided it stays manual. A script NOT listed that nothing invokes
# is reported, so a new orphan is a decision rather than an accident.
#
# These entries were reviewed and are deliberately manual:
#   * `dev:*` / `e2e` — a developer runs them at a terminal, CI cannot.
#   * `bench:*` / `smoke:*` / `stress:*` — measurement and probing tools.
#   * native `build:*` / `produce:*` / `release:*` — stepped packaging a human
#     sequences; the release workflow drives the composite scripts instead.
#   * editor-specific `vscode:*` — the VS Code host fires them, not a shell.
#
# Removing a script from its package.json, or wiring it into a gate, makes its
# entry stale and the check reports it so the ledger cannot rot.
#
# Regenerate with:
#   ./tools/review/zig-out/bin/review --check=scripts-wiring --json
