# llm Module Guide

llm is a standalone LLM request library inside the human layer (`src/human/llm/`) that provides the complete capability of "a single LLM request": request encoding/decoding across multiple protocols (openai / openai-responses / anthropic / google-genai), streaming events, thinking, media, error classification, retry and recovery, and provider/model catalog management. It neither depends on nor is aware of any external agent framework; all responsibility boundaries and extension mechanisms follow the design principles below.

## Design Principles

1. **Minimal boundary: llm = "a single request"**. The core composes a request with `createRequester().with(...)` and returns an `LlmOutcome` from `generate`. Request content uses `Message` values carrying optional `MessageAttributes`, preserved through resolvers and legalization and converted once when lowering to `NativeModule` (including rendering tool error/empty status for the model); outcomes contain `AssistantMessage` values with actual model, usage, finish, and response `attributes`. The library does not own provider catalog refresh state, session usage ledgers, compaction, switch, the media file system, or turn orchestration. There is no second requester, outer `HistoryEntry` wrapper, or compatibility event vocabulary.
2. **Streaming-native; outcomes and events have separate roles**. Core request execution returns `done / failed / aborted` as an `LlmOutcome` and emits `LlmRunEvent` values as they arrive. Completed, failed, interrupted, and retrying partial output all use the same `AssistantMessage` construction. Retry events carry partial output for diagnostics and stream resets without appending it to history; Loop appends only the final outcome message without reconstructing model metadata. `streamLlmRequest` exposes that same union as an `AsyncIterable` for transports, ending with `llm.ended` and its outcome. Streaming and non-streaming share the decoder: `stream: false` uses `send` and replays the complete response through it. The event vocabulary is `llm.started / requested / queued / notice / delta.* / retry / ended`; generation failures are returned directly and tool-call boundaries use decoder callbacks rather than `attempt.*` events.
3. **The pipeline masks inter-protocol differences; protocol patches express provider customizations**. Every protocol is a `defineProtocol` object (`packages/core/src/llm/protocol/protocol.ts`): `runPipeline` composes the encode stages (cacheKey → thinking → responseFormat → maxOutputTokens → sampling → tool → message → mergeTurns → annotate → finalize → flatten), with legalize passes for media, tool-call ids, provider patterns, thinking history, and model rules. A protocol also provides its stream decoder, non-streaming replay, error decoder, and client/send/sendStream transport. Providers derive protocols with `protocol.with(patch)`; Kimi lives in `packages/core/src/llm/builtin/provider/kimi/protocol.ts`. Endpoint declarations and environment resolution use the shared implementation in `packages/core/src/llm/endpoint.ts`.
4. **Two-layer error model**. Local validation throws `SyntaxRequestFormatError` from `llm/protocol/errors.ts`, converted by `toLlmSyntaxErrorMessage`. Protocol and transport failures become `LlmErrorMessage` values inside a failed `LlmOutcome`, preserving status fields, raw errors, request ids, and protocol-provided diagnostics. A protocol can implement `diagnoseError` to extract provider-specific details from the current attempt instead of exposing a generic `traceId`. Callers consume these core error values directly without a second error union.
5. **Immutable requester configuration + scoped execution memory**. A core requester is an immutable composition of protocol, endpoint, model, profile, content, and policy dimensions. Derived requesters share an execution context containing reusable in-memory recovery entries, while each generate restores an independent ledger so concurrent calls remain isolated. Ordinary Turns and side operations reuse these entries; a successful Loop reset clears them so Undo and history replacement do not inherit stale rewrites. `ProtocolAdapterRegistry` initializes configuration at a Turn or operation snapshot; `AgentLoopService` is the only long-lived owner of the Agent-level request facade and its execution context. Other Agent services use `loopService.requester` for side requests, credentials, upload capability, and request snapshots rather than injecting another requester service. Structural projection and media resolution run per attempt through registered policies, while outer retry remains with the turn machine and Loop. Credential recovery uses the shared core policy. Reusable media entries capture stable media replacements instead of old request messages or resolver closures. The settle stage owns the attempt-scoped message accumulator, emits normalized streamed parts, validates completed tool-call arguments against resolved tool descriptions (including deferred entries), judges empty responses, records timing, emits `llm.requested` with the legacy request summary at each attempt, and synthesizes the outcome. Invalid arguments produce an `invalid_tool_arguments` retry without executing the call; the next attempt carries only a temporary system validation reminder instead of the rejected call, and that reminder is not persisted to the conversation journal. Each retry/recovery attempt creates a fresh accumulator; Loop consumes the final `AssistantMessage` for completed and interrupted history instead of maintaining another accumulator.
6. **No silent fallback**. Configuration is used exactly as given. Unsupported beta features, thinking settings, media, and empty responses fail explicitly rather than silently switching behavior. Argument validation is limited to newly completed tool calls; existing session history keeps its previous encoding and replay behavior. Empty arguments are accepted only when the resolved schema accepts `{}`.
7. **Every variable capability is a contribution point**. Protocol patches, media upload/degradation, usage, protocol error diagnostics, and recovery plug in around the core. The core does not import v2 DI, models-dev, or provider-catalog state.
8. **Data is data**. `LlmModelSpec` and `LlmRequest` are serializable core contracts. Core messages use the existing `imageUrl/audioUrl/videoUrl` media parts; data URLs, `kimi-file://` session references, and uploaded `ms://` file ids stay in those parts. `ModelCatalog` only owns model/provider metadata and default-model selection; it does not cache requesters or expose generate/ping. Upload capability is declared by `LlmEndpoint.files`, and media resolvers receive the model and initialized requester from Loop. `SessionMediaStore.put` stores bytes and metadata and returns a `kimi-file://` reference, while `get` reads them back. ReadMediaFile only produces references; the Media Resolver resolves them on the next request using the request model, protocol media support, endpoint files, and endpoint credential recovery. The v2 history/wire message shape remains in `src/human/message.ts`; its codec preserves roles and envelopes without introducing a second media representation.
9. **Message conversion uses a compiler paradigm**. Generic messages become protocol payloads through ordered, independent patterns followed by lowering. Tool-message conversion and media mapping are patterns too. Main-line tool-result placeholders, reasoning details, and provider-specific wire behavior remain covered by the existing tests.

## Architecture

```
llm/
├── message.ts            generic Message model (split by role; tool declarations are separate)
├── model.ts              LlmModel: pure data, provider+model+endpoint overrides
├── capability.ts / thinking.ts / usage.ts / finish-reason.ts / response-format.ts / syntax-errors.ts
├── errors.ts             two-layer LlmErrorKind (syntax | remote, each subdivided)
├── toolCallIdNormalizer.ts  streamed tool call id dedup: repeated raw ids are remapped in order
├── empty-response.ts     emptyResponseError: pure empty-response judgment; the turn raises it as llm.failed.remote at llm.done
│
├── protocol/             shared protocol layer (common across bases)
│   ├── base.ts           ProtocolName / ProtocolBase<TTrait> / ProtocolRequesterOptions / TraitContext
│   ├── format.ts         ProtocolFormat: createStreamParser(sink callbacks + resolveUsage option)
│   ├── connection.ts     ProviderConnection: endpoint env declaration + default headers
│   ├── thinking.ts       ThinkingStrategy → ThinkingContribution → applyThinking → AppliedThinking
│   └── patterns.ts / rewrite.ts   MLIR-style Pattern Rewriter (Message N:M conversion)
│
├── requester/
│   ├── requester.ts      LlmRequester.generate(config, content, control);
│   │                     ExtraParams typed per protocol {openai?, responses?, anthropic?, googleGenai?};
│   │                     LlmRequestConfig.credentialProvider: credential contribution point
│   │                     (resolve/canRecover/invalidate), resolved per attempt by the caller;
│   │                     factories and the credentialsRecovery strategy live in human/credentials
│   │                     (createStaticCredentialProvider / createOAuthCredentialProvider; createKimiOAuthCredentialProvider adapts
│   │                     Kimi OAuth tokens); the runWithCredentialRecovery /
│   │                     streamWithCredentialRecovery executors for direct callers live in
│   │                     src/llm-adapter/model/credential-recovery
│   ├── actor.ts          request actor: a fromCallback wrapping a single request
│   │                     (messageResolvers, abort scope, event sendBack); invoked by the turn
│   ├── retry.ts / recovery.ts   pure retry/recovery policy functions (driven by the turn machine; propose is pure)
│   └── bases/            five protocol bases: openai / openai-responses / anthropic / google-genai / antigravity
│                         each with contract / format / lower / patterns / capability / extra-params / trait / requester
│                         (public seam: contract / trait / requester; format / lower / patterns stay internal)
│
├── provider/
│   ├── definition.ts     ProviderDefinition{id, protocols{base+trait+connection+classifyError+capability}, media, models}
│   │                     createProvider() (no registry) → Provider{listModels, resolveModel, createRequester}
│   └── providers/        built-in providers such as standard (registered via contribution points)
│
├── provider-catalog.ts   xstate machine: refresh/upsert/remove/ping in, changed out;
│                         provider -> models structure; remote pulled vs local models dual sources of truth
│
└── media/                media contribution points: cache / degrade / ref / resolver / store / upload
```

Request lifecycle: `generate` receives (config, content, control) → the caller resolves `config.credentialProvider` into a fully-credentialed model before each attempt (the request actor on the machine path), so requests always carry fresh credentials and a credential-refresh recovery (recoverable 401 → `credentials.invalidate()`, emitted as `llm.recovering` with strategy `credentials`) naturally re-resolves on the re-send (direct callers outside the state machines — ping, generate, full compaction, media upload — share the same single-retry recovery through `runWithCredentialRecovery` / `streamWithCredentialRecovery`) → the requester's `prepare*Request` function composes pure format stages with trait hooks into protocol requestParams (format lowers the generic Message[] through the Pattern Rewriter; trait adjusts kwargs, converted messages, history, tools, and final params in between) → `execute*Request` calls the official SDK → streaming chunks are converted by the stateless parser callbacks into `llm.streaming.part / streaming.usage / streaming.finish / streaming.message_id` events → errors are converted by format into `llm.failed.*`; on success the requester emits `llm.done`, on failure it ends with `llm.failed.syntax / llm.failed.remote` and never emits `llm.done`. At `llm.done` the turn judges empty responses via `emptyResponseError` and re-raises them as `llm.failed.remote`; the turn machine first tries recovery on `llm.failed.remote` (the engine-composed strategy chain — credential refresh on a recoverable 401 first, then replacement-message strategies — each pure `propose` returning a record whose opaque `beforeNextAttempt` effect the turn executes, emitting `llm.recovering`), then retries with backoff (honoring Retry-After, emitting `llm.retrying`), and only fails the turn once attempts are exhausted. The turn holds the HistoryAccumulator, fed by the event stream, rolls it back and recreates it on `llm.retrying / llm.recovering / llm.request.retrying`, and finishes the complete message at `llm.done`; usage accounting, tracing, compaction, and media degradation all attach to the event stream as plugins/contribution points.

Tool disclosure is a request-view concern rather than an execution permission. At the final `legalize-tools` boundary, top-level declarations win (the last duplicate wins), then system messages are scanned newest to oldest; removed duplicates emit one `llm.notice` and one warning log per tool name. A `tool_lifecycle` text-part meta clears the removed names from this duplicate scan, so declarations on opposite sides of that unload boundary survive; legacy duplicates without the meta keep the last-declaration-wins behavior. This pass never deletes system messages, even when their tool arrays become empty; empty-message cleanup belongs to other passes. The Agent persists an initial registry snapshot and ordered runtime changes after MCP initialization; later requests reconcile the live registry into that ledger instead of rebuilding the initial snapshot. For capable models, the ToolSelect resolver removes deferred entries from the resolved top-level tools. The step reminder provider persists the added/removed deltas, starting with the baseline deferred names; `shapeHistory` projects an initial tool-change snapshot at the start of the messages instead when it receives the pre-shaping deferred baseline. SelectTools delivers selected schemas through system messages appended by `loop.remind`. Loaded state requires the exact active schema version. A same-name modification of a deferred or runtime-disclosed tool records removed old and added new definitions in one delta. Its announcement remains the same wrapped reminder text on every provider and carries `tool_lifecycle` meta with the added and removed names. Kimi Chat Completions lowers each non-empty removed list to an immediately following system `unload_tools` message without `content` or `type`; every delta produces its unload without checking declaration history or deduplicating across announcements. Loads remain system messages with `tools`. Before reselection, execution rejects the stale schema and directs the model to `select_tools`; after reselection, the current schema and executor run normally. A same-name modification of a purely inline tool keeps the active schema and executor pinned for the current running session and emits the existing reminder once per service instance. Models without dynamically loaded tools keep the provided top-level tools. The resolver removes `select_tools` and system tool schemas, converts lifecycle announcements to plain runtime reminders without lifecycle meta, and strips the `deferred` metadata; `legalize` retains the same deferred cleanup as a boundary safeguard for requests that bypass ToolSelect. Runtime additions are not copied into `tool[]`, and their name changes remain content-bearing reminders. Model switches never rewrite the persisted snapshot, change ledger, or context history. Explicit tool overrides remain unchanged.

## Rejected Schemes (do not reintroduce)

- Splitting the request actor into llmActor / llmStreamActor — one actor per request; non-streaming also accumulates over the stream.
- A dedicated llm state machine wrapping the request actor — the turn machine invokes the actor directly and owns retry/recovery; the extra machine layer carried no state anyone consumed.
- DDD domain-method wrapping (Generation Domain, etc.) — use the format/trait/provider layering instead.
- A single cross-protocol trait bag holding every vendor hook (the old ProtocolTrait) — per-protocol typed traits, composed by the requester's request pipeline.
- Binding the trait into the format (a `createOpenAIFormat(trait)` closure, or trait hooks passed as formatRequest options) — the requester pipeline alternates format stages and trait hooks explicitly; the two sides only share the neutral `contract.ts` types.
- Functional `toWireMessage` / `WireAdapter` naming — use an adapter interface; no "Wire" in names.
- Provider registry / `defineProvider` — `createProvider` exporting a const.
- Hoisting system messages out of their position on egress — system messages stay in place in history and are converted in place.
- llm emitting a `{message, meta}` Context object — meta belongs to the turn domain; llm only emits events.
- Implementing the accumulator once in llm and once in the turn — the accumulator is held only by the turn and fed by the event stream.
- Unlimited fallback for beta features — beta features are configured via provider extra-params; there is no separate `anthropic_beta` protocol.
