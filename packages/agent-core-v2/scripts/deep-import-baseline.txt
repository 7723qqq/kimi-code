# Cross-package deep imports into the agent engine.
#
# One entry per import site: the file that imports, then the engine module it
# reaches into. Keys name the module rather than the line, so ordinary edits
# above an import do not churn the ledger, and an entry that stops matching is
# reported so the ledger cannot rot.
#
# Three shapes are legitimate and never reach this file:
#   * a type-only import, erased before bundling;
#   * a DI service identifier (`I*Service`), whose narrow module is what keeps
#     the engine's implementation and its \`?raw\` assets out of a consumer that
#     bundles it (klient, for one, cannot load those assets at all);
#   * an import of a module the engine's root entry already re-exports — those
#     are reported, not baselined, because redirecting them is mechanical.
#
# Everything listed below is an accepted exception, reviewed at the time the
# check was introduced. Shrink the list; do not grow it without recording why.
#

#   bun packages/agent-core-v2/scripts/check-deep-imports.mjs
