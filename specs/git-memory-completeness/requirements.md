# Requirements — 让 agent 知道仓库全貌

## 目标

现有 `git_memory` 记忆层把仓库的历史投影进上下文，但覆盖面窄到读不出一个仓库：

- L1（系统提示）只有**最近 5 个提交**，且每条只有 subject 首行；
- L3（工具结果）只有该文件**最近 3 个提交**；
- 索引里已经缓存了 1500 个提交的窗口，除了这三层之外**没有任何通道暴露**；
- 仓库的**文件与目录结构**（本仓库 5664 个文件、1063 个目录）完全不进上下文。

结果是：模型知道"最近有人动了哪几个文件"，但不知道**为什么动**（commit body 被丢弃）、不知道**这个区域最近在忙什么**（没有目录级历史）、不知道**仓库里有什么**（只能靠十几次 Glob 摸）。

本 spec 的目标：**在不要求模型主动调用工具的前提下**，把"仓库长什么样 / 最近在做什么 / 为什么这么做"三件事送进上下文。

## 受众

- 维护 `packages/agent-core-v2/src/features/gitMemory/` 的开发者；
- 在这个仓库里跑 agent 的人，**包括不主动调用工具的模型**。

## 核心纪律（沿用 `deterministic-git-memory-pipeline` 的 R4，不放松）

> **注入内容只能是 git 对象的原始投影。**
>
> 允许：sha、commit message 原文（含 body）、author、date、分支名、该提交的路径列表、目录树原文、已提交文件的原文。
> 禁止：任何由这些对象**计算**出来的描述——计数、频率、排名、共现次数、占比、"通常一起改"、"你必须同时改 X"。

新增的两类载荷都不产生派生量：

- **commit body** 是 git 对象里已有的原文（`git log --format=%b`），不是计算结果；
- **目录树**是 git 对象里已有的原文（`git ls-tree`），深度筛选是结构性选择规则，与"取最近 N 个"同级。

## 实测依据

本仓库（3988 提交、5664 受版本控制文件）：

| 载荷 | 体量 | 备注 |
| --- | --- | --- |
| 最近 25 个提交的 `%B`（subject + body） | 2,779 字符（当前窗口）／典型 25×330 字符 | 最近 100 个提交里 65 个有非空 body，共 32,991 字符 |
| 最近 25 个提交的路径列表 | 14,497 字符 | 路径列表是召回载荷的主体 |
| 全部目录（`git ls-tree -d -r`） | 1,063 条 / 43,380 字符 | |
| 深度 ≤3 的目录 | 170 条 / 3,882 字符 | |
| 全部文件（`git ls-tree -r`） | 5,664 条 / 298,674 字符 | 放进系统提示不可接受 |

body 的实际内容是"为什么"：例如 `7700cec70a` 的 body 解释了 `walk.joinPath` 在 Windows 上产出反斜杠路径、导致四个分类器全部返回 false 的完整根因。这类文本**当前完全不在上下文里**。

## 需求

**R1 L1 注入最近 25 个提交，每条带完整 commit body。**
每条含：sha(7)、date、author、subject 原文、**body 原文**、该提交的完整路径列表。路径列表沿用既有规则：单组提交触碰文件数 > 25 时不列路径。

**R2 L1 注入 HEAD 的目录树，深度 ≤ 3。**
内容是 `git ls-tree -d -r --name-only HEAD` 的原文行，按路径深度筛选。独立标签 `<repo-tree depth="3">`。

**R3 L3 注入该文件最近 8 个提交，每条带 body。**

**R4 L3 追加该文件所在目录最近 5 个提交。**
规则："取路径列表中含该目录前缀的提交"。作为 `<file-memory>` 的子段 `<dir-memory path="...">`。

**R5 索引的倒排表不再按路径截断。**
`byPath` 保留窗口内该路径的全部提交位置，支撑 R3/R4 与更深的历史。

**R6 新增 `RepoMap` 工具。**
`RepoMap({ path?, depth? })` 返回 `git ls-tree -r -t --name-only HEAD -- <path>` 的原始路径行，按 depth 过滤。目的是让模型一次调用拿到子树结构。

**R7 所有新通道由 `git_memory` flag 控制。**
flag 关闭时：三层注入与今天逐字相同，`RepoMap` 工具不注册，不 spawn 任何 git 进程。

**R8 取数只允许窗口扫描，缓存命中时零 git 进程。**
新增的取数动作（读 body、读目录树）必须并入已有的 git 调用或新增到同一次索引重建里，不得在注入路径上追加 git 进程。

**R9 缓存格式变更必须让旧缓存失效。**
索引版本号递增；旧缓存被丢弃重算，不做兼容解析。

**R10 失败必须降级且留痕。**
git 缺失 / 非仓库 / 超时 → 不注入，`log.debug`/`log.warn`。目录树取不到 → 只少 `<repo-tree>`，其余照常。

**R11 注入文本是 C2 模型资产：英文、不翻译、不加 locale key。**

**R12 注入内容是数据，不是指令。**
commit body 来自上游贡献者，是不可信文本。保持标签边界清晰，不给它指令语义。

## 决策记录

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | body 走索引缓存，不在渲染时单独取 | R8 要求缓存命中零 git 进程 |
| D2 | 目录树缓存**全部**目录，深度筛选在渲染时做 | 深度是渲染决策，改一次不用重算索引 |
| D3 | 目录历史走运行时前缀扫描，不进倒排表 | 1,063 个目录各存一份位置表会让索引膨胀到不可用 |
| D4 | `RepoMap` 放 feature 目录内并由 flag 控制注册 | 与 `WaitFor` 的 `when:` 写法一致；默认用户感知不到 |
| D5 | L1 提交数取 25 而非更多 | 25 条含路径列表约 17k 字符；再往上收益递减而提示词线性变长 |
| D6 | L3 目录历史给 5 条 | 目录历史是补充而非主载荷；文件自身的提交列表已经承载共变信息 |

## 排除范围

- **不做任何统计型记忆**（共现、频率、排名、占比、模块划分）。
- **不把完整文件清单放进系统提示**（298,674 字符 ≈ 75k token）。
- **不注入 diff 正文**（体量随历史线性增长）。
- **不引入向量检索、不做 LLM 摘要、不做检索 agent**。
- **不改 L2（reminder 通道）的载荷**。
- **不改 `deterministic-git-memory-pipeline` 已发布 spec**——它记录的是当时的契约，本 spec 是它的后续。
