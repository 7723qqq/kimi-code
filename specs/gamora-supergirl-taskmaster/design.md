# Design — 关联记忆的完整优化计划

需求见 `requirements.md`，验收见 `tasks.md`。本文只写落点与取舍。

## 0. 一句话

把三个死字段/死语义变成活的：`baseWeight` 承载显著性并参与打分与衰减，容量淘汰按可及性而非年龄，抽象层的排序问题先量化再决定；同时用"先测后改"处理模式分离。

## 1. R1 显著性（`baseWeight` 变成参与者）

### 现状

`baseWeight` 只在三处出现：编码时置 1（`encode.ts:131`）、`pin` 时 +1（`service.ts:471`）、类型声明（`types.ts:25`）。没有任何读取点，因此 `pin` 的加一是纯粹的空操作，`pin` 的实际效果只剩"排除出衰减"（`decay.ts` 的 `pinnedIds`）。

### 落点

1. **种子打分**（`activate.ts` 的 termSeeds 循环）：把 `baseWeight` 乘进种子分数，作为有序放大因子。取 `1 + (baseWeight - 1) * SALIENCE_GAIN`，`SALIENCE_GAIN` 为常量、上限封顶，避免"钉一条就霸榜"。
2. **衰减抵抗**（`decay.ts` 的 `applyDecay`）：在既有的 LTP 因子之后，再乘一个由 `edge.strengthenCount` 与端点 `baseWeight` 决定的因子。端点显著性越高，有效年龄越小。
3. **可观测**（`activate.ts` 的 trace 输出）：`RecallTraceNode` 增加可选的 `salience` 字段，`explain` 原样透出。
4. **淘汰排序**（见 §2）：作为可及性的一个分量。

### 契约

- `Atom.baseWeight` 语义固定为"显性强度"，默认 1，`pin` 时 +1（保持现状），被显式加权时单调增加。
- 新增常量集中在 `params.ts` 或模块常量区，不新增用户可配项（避免又一批调不动的旋钮）。

### 被否决的方案

- **把显著性做成 LLM 判断**：违反"不把 LLM 放进写路径"的边界。
- **用笔记文本启发式识别"用户要求记住"**：不可判定、会产生误判，且无法写可复现的断言。
- **给 `writeNote` 加 `weight` 参数**：会把显著性判断推给模型，等于把目标函数外移。

## 2. R2 可及性淘汰

### 现状

`enforceBudgets` 对存活原子按 `lastActivatedAt` 升序取最旧的淘汰。这与 R3「权重低于阈值才剪枝」是两套语义：一个按时间，一个按强度。

### 落点

定义可及性分数（纯函数，放 `decay.ts` 旁）：

```
accessibility(atom, edges, now) =
    decayFactor(now - atom.lastActivatedAt, params)   // 时间维度
  × (1 + log1p(incidentWeightSum) )                    // 结构维度
  × max(1, atom.baseWeight)                            // 显性维度
```

- 只统计未被剪枝的入射/出射边权重和。
- 淘汰时候选按 `accessibility` 升序，`pinned` 仍排除。
- 分数相同则以 `id` 排序，保证确定性。

### 契约

- `accessibility` 是导出纯函数，签名 `(atom, edges, now, params) => number`，可单测。
- 淘汰路径的审计与墓碑语义不变。

### 被否决的方案

- **直接用权重和排序**：忽略时间，会让很久没用的高连通旧记忆永远存活，与遗忘曲线冲突。
- **按"最后使用时间 + 重要性"两段排序**：等价于上面的加法版本，但无法表达量纲差异，故采用乘性组合。

## 3. R3 概念/程序影响力（先量化后决定）

### 现状

实测：分散 cue（5 词分属 5 个成员）下概念排第 3，原子在前。加前缀匹配后更明显，因为原子能匹配更多词。

### 落点

分两步，**先只做第一步**：

1. **量化**：新增 `conceptRanking.test.ts`，对"跨 ≥3 成员"的 cue 重复 3 组，记录概念的排名分布。判据写成断言：概念进入前 3 为通过（当前行为），并额外记录"是否首位"作为诊断值。
2. **决定**：若首位比例 < 2/3，则维持现状，并在 `memoryGraph.md` 写明"概念是压缩节点，不保证排在原子之前"。若 ≥2/3（即某次改动已让它占首），则把断言收紧为"首位"，防止回退。

### 契约

- 判据写死为常量并在断言里命名，避免"看一眼觉得还行"。

### 被否决的方案

- **给概念加固定权重乘子把它推上首位**：这是拟合测试而非修问题，且会让窄 cue 也被概念劫持。
- **把概念从召回结果里去掉**：与 R4「概念层参与扩散」冲突。

## 4. R4 死状态清理

- `note.atomIds`：确认无读者后，从 `types.ts` 的 `NoteRecord`、`service.ts` 的 `putNote` 调用、以及任何构造点删除。`rebuild` 按 `note.text` 重训，不依赖它，须补一条断言证明重建后仍可召回。
- `baseWeight`：被 R1 启用后保留；若 R1 未落地则一并删除。

### 被否决的方案

- **把 `note.atomIds` 做成权威**（每次原子生命周期变更都同步）：需要跨写路径的一致性维护，成本远高于收益，而真正被用的是"按 noteId 反查原子"。

## 5. R5 模式分离（先测量后决定）

### 落点

1. 构造语料：同一主题下**结论冲突但措辞相近**的两条（如 "the cache ttl is 30 seconds" / "the cache ttl is 60 seconds"，以及更长版本的近重复）。
2. 测量三件事：两条是否被合并成一条（NOOP 误判）、是否互相压制（抑制边导致只出一条）、是否都缺席。
3. 仅当出现"应当并存却只返回一条"的可复现现象时，才在 `train.ts` 的关联判定里加入分离条件（例如"词集余弦高但差异词不为空 → 建 `inhibits` 而不建 `hebbian`"）。

### 被否决的方案

- **直接引入正交化（正交化向量）**：需要新的向量表示与迁移，且没有实测证据表明当前存在该问题。

## 6. 顺序与依赖

```
T1 可及性纯函数 ──┐
T2 显著性进打分 ──┼─► T4 淘汰改为按可及性
T3 显著性进衰减 ──┘
T5 观察面（explain/stats）—— 可与 T2/T3 并行
T6 死状态清理 —— 依赖 T2/T3 的结论
T7 概念排名量化 —— 独立
T8 干扰测量 —— 独立
```

## 7. 风险

| 风险 | 处理 |
| --- | --- |
| 显著性把 `pin` 变成"霸榜开关" | 增益封顶 + 断言"未被 pin 的强关联仍可超过一次 pin" |
| 可及性公式权重拍脑袋 | 只做排序用途，不参与阈值判断；断言写成"谁该活谁该退"的对比，不写具体数值 |
| 概念判据被新改动打破 | 断言固化，进 CI |
| 死状态删除破坏重建 | 单列一条 `rebuild` 断言 |
