# 多记忆模块隔离与生命周期修复

## 目标与使用者

面向在多个项目、多个会话和多个 agent 之间使用 Kimi Code 的用户，完整处理本轮审查发现的七项问题：知识库实例串用、旧记忆迁移丢失归属、Git 自动记忆跨项目注入、知识规则适用范围失守、注入去重生命周期错误、Git 成功缓存不失效、联想记忆历史正文常驻增长。

交付结果是可运行的实现、逐项回归测试、兼容性说明及验证证据，而不是仅提交建议。按优先级分批完成，但批次验收不是等待用户发送“继续”的节点。

本规格以当前源码为基线，项目通用约束引用 [DEVELOP.md](../../DEVELOP.md) 与 [CONVENTIONS.md](../../CONVENTIONS.md)，不在这里重复。

## 已知基线

- 已审查文件长期记忆及其 Git 仓库、Git 历史记忆、知识库、联想记忆和上下文压缩之间的主要链路。
- 前一轮相关局部测试为 28 个文件、294 项通过；这只是审查时的结果，不作为本次修改后的验收证据。
- 七项问题已有源码证据及生产方法的合成复现；其中去重的跨 agent 场景已复现，压缩后的完整会话场景仍须补成集成测试。
- Git 与联想记忆的实验开关在源码中默认关闭；本任务不改变默认值，也不读取用户私人配置或记忆库。
- 工作区已有其他任务的未提交修改；本任务只处理记忆修复相关差异。

## 默认决策

1. 保留现有模块分工，修复边界与生命周期，不重写成一个总记忆系统。
2. 自动注入采用“全局＋当前规范化项目＋当前会话”的可见集合；主动跨项目搜索的既有能力保留。
3. 沿用 `projectIdentity.ts` 的项目身份规则，包括同一远端仓库共享项目身份的现有行为，不在本次重新定义项目边界。
4. 历史数据作为应保留的规范记录存在磁盘上，不用删除历史、弱化测试或关闭功能来消除问题。
5. 不自动删除、移动或重新归类已经污染但无法证明原始来源的真实用户记忆。

## 功能要求与验收条件

### R1 — 知识库实例隔离（P1）

- 每个 `AgentKnowledgeService` 必须持有明确的数据库连接身份；一个实例打开、切换、关闭或打开失败，不能改变另一个实例的操作目标。
- 默认项目数据库路径由会话工作目录解析，而不是无条件使用应用启动目录。显式数据库环境覆盖仍按原有优先级生效。
- 保留 SQLite 表结构、条目 ID、JSON 返回字段、确认阈值和已有数据；读取不存在的库不得创建文件。
- A/B 两个实例交错读写时只能访问各自目标库。释放 B 后 A 仍可操作；正常释放实例不遗留数据库连接。
- 现有根导出 `knowledgeClose()` 继续可调用，作为显式进程级清理操作；清理后服务必须识别连接已关闭，不得保留虚假的 initialized 状态。

### R2 — 旧记忆按归属迁移（P1）

- 当前项目只能导入全局、当前项目（含已知旧身份别名）与当前会话的旧记忆。其他项目/会话不写入当前项目，留待对应会话按需处理。
- 保留原始 path、scope、scopeId 与内容指纹的可追踪关系；会话记忆不能提升为项目记忆。
- 迁移具有持久化的记录级完成标记；重复访问、并发 agent、关闭后重开，不重复生成相同迁移版本。
- 同一路径内容改变时可迁入新版本，旧版本按历史语义保留；只完成一部分时，不把未完成项标成成功。
- 某条迁移失败、被写入规则阻止或目标被其他进程占用时，原始内容保持不变，有可观察诊断，后续可以重试。
- 不因一个 agent 的局部迁移而把整个应用级旧存储冻结。联想功能关闭时，原有 Memory 工具仍按既有规则可用。
- 来源不明的既有联想记录不凭文字相似度自动归属或删除；修复阻止继续污染，不宣称已自动修复不可追溯的历史污染。

### R3 — Git 自动投影的作用域边界（P1）

- 在 `repoBlock` 和 `fileBlock` 投影之前，先校验长期记忆的可见范围，再匹配 `applies_to`。
- B 项目/旧会话的记忆即使没有 `applies_to`、有相同文件名、命中相同 glob 或已提交到记忆 Git 仓库，也不得进入 A 的自动投影。
- 全局、当前项目与当前会话的合法记忆继续进入投影；无效路径/未知 scope 采用不注入策略。
- 主动 Memory 搜索与读取的既有跨项目行为不被这项自动注入修复顺带移除。

### R4 — 知识规则的自动注入边界（P2）

- 自动查询中的路径、全文、标签三种召回渠道必须使用相同的适用范围限制，且在限制后执行候选数量上限和排名。
- 没有文件线索时，仅注入全局或适用于当前项目根的规则，不猜测某个子目录规则适用。
- 明确区分自动注入与主动搜索：主动搜索保留既有宽范围检索，自动注入不能把相关性分数当权限/适用性。
- 覆盖目录边界、相对与绝对路径、Windows 分隔符和盘符大小写；`repo` 不能匹配 `repo-old`。
- 即使有超过候选上限的其他项目高相关条目，也不能挤掉当前范围中应当返回的条目。

### R5 — 注入去重与上下文生命周期一致（P2）

- 去重所有权至少包含 session、agent 与上下文前缀版本。同一 agent 的普通追加不重复注入；独立 agent 不能互相消耗注入机会。
- 清空、压缩、恢复或其他导致旧注入不再有效的上下文重写后，相同合法记忆能够再次注入。不能改变原有上下文版本的其他消费者语义来偷换实现。
- Git 本地路径/commit 去重和跨记忆来源的正文去重必须一起失效，不能只清理一层。
- 只有实际进入返回文本的项目才能标记为已渲染；因渲染上限被略过的项目不能永久丢失注入机会。
- agent 释放后，其去重状态可回收，不保留跨 session 的无界全局表。

### R6 — Git 成功缓存刷新（P2）

- 每个新用户回合检查当前仓库 HEAD；同一回合的连续文件读取允许短时复用检查结果。
- 普通入口的成功 HEAD 检查复用窗口为 2 秒（可注入时钟测试）；显式新回合强制检查不受窗口阻挡。
- 提交、checkout、分离 HEAD 等引起身份变化后，后续投影切换到新索引，并清理与旧索引有关的渲染缓存。
- 同一目标的并发检查/构建合并；旧异步构建完成后不能覆盖较新的 HEAD 索引。
- 保留既有失败冷却、损坏缓存重建和可用旧快照降级，但旧快照必须可识别，不能伪装成当前 HEAD 的事实。
- 系统提示词中的初始仓库记忆可保留为带 HEAD 的快照；新回合发现变化时通过现有 reminder 通道提供当前快照，不为每次提交重建整段系统提示词。

### R7 — 历史保留与常驻工作集分离（容量设计）

- 复用 MiniDb 的磁盘 value mode，保留现有 canonical keys 与历史正文，不另建第三套数据库或双写迁移系统。
- 非 pinned 的活跃原子沿用 4000 上限，普通 note 工作集沿用 8000 目标；pinned、活跃图实际引用的数据必须保留，不能通过隐式淘汰破坏 pin 语义。此类例外须明确计数。
- 被淘汰/过期的原子及其无活跃引用的笔记不能长期保留在服务 Map 或 MiniDb 的内存 value 副本中；正文/向量按需读取。
- `includeHistory`、list、stats、export、rebuild、pin、forget、reconsolidate 和重复检测必须正确跨越热/冷边界；已显式删除的内容不得因重开或重建重新参与正常召回。
- 旧 memory-mode 数据可无损以 disk mode 打开；generation 模式不匹配不得被误判成可以清空的数据损坏。
- 固定活跃预算和 pin 数量，将合成历史从 20 增至 2000 条后，常驻正文/向量工作集数量仍满足相同界限。正常召回不扫描历史正文。
- 不承诺整个进程 RSS 为常数：MiniDb 仍保留随记录数量增长的键/位置元数据。明确历史查询可能消耗与所查询历史量相关的临时内存，不把它计成常驻缓存，也不静默截断历史结果。

## 整体验收

- 每项问题有能复现旧行为、证明新行为的回归测试；失败注入覆盖迁移/数据库打开/缓存异步发布的关键边界。
- 每阶段局部测试通过后继续下一阶段；最后执行拥有包回归、受影响消费者测试、类型检查与相关现有 gate。
- 完整运行合成 A/B 项目场景：交错读写 → 迁移 → 自动注入 → fork/独立 agent → 清空/压缩 → HEAD 改变 → 历史淘汰 → 关闭重开。
- 所有验证使用测试 fixture，不读取实际私人记忆；无新增依赖、无遗留临时目录、无无关工作区差异。
- 最终报告逐项标明完成证据、数据兼容边界和真实阻塞；不能将上一轮通过结果或源码推断当成修改后验证。

## 明确不做

- 不重新设计检索算法、embedding 服务、模型提示词、DeepSeek 适配层、UI 或全仓记忆产品形态。
- 不改变实验开关默认值、数据库环境覆盖优先级、主动跨项目搜索的既有入口。
- 不自动清理无法追溯的污染数据，不删除历史来达到容量指标，不声称修复前发生过的真实泄露已被消除。
- 不发布、不提交、不推送、不构建部署系统 exe；这些不属于本次实现请求。
- 不修复其他客户端正在修改的 UI 或其他无关失败。
