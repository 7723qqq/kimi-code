# Requirements — Updates 面板的鼠标交互改回「与其他折叠一致」

## 背景

上一轮我为 Updates 面板加了鼠标支持，但实现方式被用户否决：

> 你是通过拦截实现的？这不合适 要让他能像其他折叠一样交互而不是我鼠标在这里滚动一些就视为 ctrl+n

具体错在哪（已核实）：

1. **滚轮调用了 `focus()`** —— 把「滚动浏览」等同于「按 Ctrl+N 抢占键盘焦点」。用户一滚鼠标，后续按键就被面板吞掉，这是把浏览和聚焦混为一谈。
2. **被迫这么做是有原因的**：`render()` 里写着 `if (!this.focused) ch.scroll = 0`（未聚焦强制回到顶部），所以不抢焦点就根本滚不动。也就是说，真正该修的是这个「用焦点模拟滚动状态」的设计，而不是在外面绕。
3. **`+N done` 的展开只靠点击标签** —— 而仓内既有的折叠交互是「点击整行切换」，不是「点一个小标签」。

## 目标

让 Updates 面板的鼠标交互**沿用仓库既有的折叠协议**，而不是发明一套。

- 滚轮：滚动当前更新，**不夺键盘焦点**；向上滚停止跟随、回到底部恢复跟随（对齐 `BtwPanelComponent` 的 `followTail`）。
- 点击：**点击面板任意位置**即切换「展开/折叠」，与 transcript 里点击工具卡、点击 ctrl+o 块的行为一致。
- 被折叠（未展开）时，面板只显示一行 stub；点击该行展开，点击已展开的正文折叠。

## 受众

仓库维护者（本 fork owner）。验收须能用渲染 + 鼠标事件断言，而不是靠肉眼。

## 范围内

- `apps/kimi-code/src/tui/components/chrome/notify-panel.ts` 的交互模型（`followTail`、展开态、鼠标处理）。
- `apps/kimi-code/src/tui/tui-state.ts` 与 `kimi-tui.ts` 的接线（若需要注册点击兜底）。
- 相关测试、i18n 文案、docs、changeset。

## 明确不做

- **不拦截滚轮**：滚轮不返回 `handled: true` 去阻止传给 transcript 之外的行为——修正为「在面板区域内滚动面板」，区域外仍归 transcript。是否 `handled` 只在指针确实落在面板内时成立，这一点由布局命中测试保证，不需要额外拦截。
- **不用滚轮抢焦点**：滚轮只改滚动状态，不改键盘焦点。
- 不改频道折叠（`+N done`）的语义，只改它的**交互入口**。
- 不改上游的频道模型（一 agent 一频道），本轮只碰交互。
- 不引入新的键位。

## 与上游差异

鼠标交互上游完全没有（已核实 `upstream/main` 的 `notify-panel.ts` 无 `handleMouse`）。本轮的策略是**尽量复用仓内既有协议**（`Expandable` 能力接口 + `GutterContainer.setUnhandledClick` + `followTail`），把这些偏离收敛成「用已有机制接线」而不是「新造机制」。
