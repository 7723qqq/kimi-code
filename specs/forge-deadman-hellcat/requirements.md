# 全屏 TUI 鼠标点击：需求

## 目标和对象

让使用 Kimi Code CLI 全屏终端界面的用户能直接点选模型思考强度、切换和查看后台任务、查看和退出审批预览；同时修复点击丢失、点到旧行或点穿界面的情况。先交付本规格，审批后才修改实现。

## 鼠标边界（已确认）

- **R1 · 沿用终端标准上报。** 只使用现有全屏终端会话已经发送的鼠标事件。不开新的或更强的追踪模式，不新增全局鼠标监听、系统级钩子、窗口捕获、轮询或输入注入。控件在自己的可见命中范围内响应，不新增全局输入拦截或透传重放。
- 全屏上报的状态、普通模式、终端兼容回退均保持现状。终端原生选字、菜单或应用链接能否与上报共存，取决于终端本身；不承诺关闭上报后仍可用普通左键操作。没有上报时，键盘依然可操作。

## 行为与验收

| 编号 | 用户可见的验收行为 |
| --- | --- |
| R2 · 点击可靠性 | 本次补齐的控件以一次同目标的无修饰左键按下/松开触发一次；支持终端现有的 SGR 明确释放和通用释放。孤立松开、拖出再拖回、不匹配的按钮、从失焦保护期遗留的手势、换根画面/改尺寸/被新浮层遮住后的旧手势均不触发新动作。边距、分隔符、裁掉或禁用的目标不冒充可点击控件。仅刷新样式或输出、没有换掉目标的重绘不应吃掉点击。 |
| R3 · 模型选择 | `/model`（含无标签版本）点击可用的思考强度分段只更改所选模型的草稿；`Enter` 或现有提交键仍负责生效。单一/禁用分段和截断后不可辨认的分段不触发。点击实际可见的供应商标签只切标签，不选中或提交模型。 |
| R4 · 后台任务 | `/tasks` 和停靠的任务迷你面板可点实际可见的 `全部 / 运行中 / 已结束` 标签及任务行。点行只选中它；切到详情/返回列表走现有查看输出、返回动作。迷你面板的放大、关闭走同一组已有回调，关闭后恢复输入焦点。任务刷新、列表变空、切详情或缩窗后，不能用上一帧的行号选中另一条任务；详情正文仍可拖选。 |
| R5 · 审批预览 | 展开的审批有差异或文件内容时，可点可见的预览入口打开同一个只读预览；预览中可滚读、点返回，恢复原审批的焦点、选项及输入草稿。打开、滚动、关闭、空白点击都不得发送审批结果；未展开、没有可预览内容或按钮无法容纳时无可点入口，原键盘路径保留。 |
| R6 · 既有操作不退化 | 既有编辑器光标、补全选项、会话折叠、粘顶消息、跳到底部、搜索和滚动条继续工作；既有列表/表单、问题对话框、审批选项和 Updates 的点击与焦点规则保持。全屏正文拖选复制（含 `copy_on_select` 两态）、OSC 8 链接、平台已有的右键粘贴与普通模式行为不变。首击只交接焦点、审批与对话框的稳定窗口按现有规则执行，不扩大它们的提交范围。 |

## 不做

- 不把说明行、统计、日志、正文、队列显示、抽样反馈或所有键位提示一概变成按钮；不把停止任务、删除、重置等现有仅键盘复核的动作加到鼠标上。
- 不重做选择、剪贴板、URL 打开、滚动器、键盘协议或终端宿主；不新增配置开关、环境变量、依赖、权限或新的 CLI/SDK 行为。不涉及 Web、VS Code 扩展或桌面 UI；VS Code 集成终端只作为 CLI 的终端宿主验证。
- 不依赖网络、真实账号或真实有副作用的审批来验证。端到端用本地测试替身执行组件回调；真实终端验收记录实测宿主，不能验证的平台明确标明。
