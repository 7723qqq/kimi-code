# Requirements — git 原始投影作为记忆层，与系统提示并存

## 目标

给 agent 一个**不需要主动查询**、**可审计可回滚**的记忆层，与系统提示**并存**。

核心纪律（贯穿全文）：

> **注入内容只能是 git 对象的原始投影。**
> 允许：sha、commit message 原文、author、date、分支名、该提交的路径列表、diff/stat 原文、已提交文件的原文。
> 禁止：任何由这些对象**计算**出来的描述——计数、频率、排名、共现次数、占比、"通常一起改"、"你必须同时改 X"。
>
> 选择规则可以是结构性的（取最近几个、取哪些路径），但被选中的内容必须**逐字来自 git**。

这条纪律来自两条独立理由：其一，**让 AI 参与注入就有不稳定性，再强的模型也会幻觉**；其二，注入必须能被复核——逐字来自 git 的内容可以用 `git show` 验证，统计描述不行。

## 受众

- 维护 `packages/agent-core-v2` 中工具结果组装、agent profile 组装、reminder 通道的开发者；
- 使用者：在这个仓库里跑 agent 的人，**包括不主动调用工具的模型**。

## 目标函数：省 token 是错的目标

```
E[成本] = P(漏掉必改文件) × C(一次改错) + 注入量 × 1
```

| 项 | 量级 |
| --- | --- |
| 注入一份文件画像 | 800–1700 token |
| 改错一个文件 → 测试红 → 回读 3–5 个文件定位 → 再改 → 再跑测试 | 20K–60K token，3–10 轮 |

比值 **1:12 到 1:35**。所以不设 token / 字符上限，也不优先保精度——漏掉导致失败回环，多给几个无关路径只是多扫一眼。

## 实测依据

1500 提交窗口，按时间切分（train = 较老 851 个可用提交，test = 最新 212 个，过滤 2–30 文件的提交）。指标：用 train 段统计预测测试提交的文件集，算 recall / precision。

**天花板 0.639**：测试提交里 36.1% 的文件在 train 段从未出现（新文件），任何历史方法都预测不到。

### 被保留的载荷（raw 投影）

| 载荷 | 估计 token | 召回 | 精度 |
| --- | --- | --- | --- |
| **该文件最近 3 个提交的原始投影**（sha + 日期 + subject + 路径列表） | **~1660** | **0.463** | 0.053 |
| 该文件最近 1 个提交的原始投影 | ~860 | 0.385 | 0.088 |
| 该文件最近 10 个提交的原始投影 | ~2950 | 0.497 | 0.040 |

这三行就是最终形态：**内容逐字来自 git，只有"取几个"是规则**。

### 被否决的载荷（全部是"计算出来的描述"）

| 载荷 | 召回 | 为什么否决 |
| --- | --- | --- |
| 全局 top-500 共变对（PMI 排序） | 0.006 | 统计量，且实测无效 |
| 全局 top-5000 共变对 | 0.037 | 同上 |
| 全局目录共变图 cap 15 / cap 400 | 0.039 / 0.039 | 同上；加到 8992 token 也不涨 |
| 按提交前缀的变更配方 topN=10 | 0.123 | 同上 |
| 共变图连通分量（"模块"）score≥0.15 / 0.20 / 0.30 | 0.282 / 0.221 / 0.123 | 同上；54–82% 的文件在共变图里没有强边 |
| 最近一次变更压成目录 | 0.647（**仅目录层**） | 是派生描述，且丢掉文件层信息 |
| 高精度共变伙伴 | 0.103 | 是派生描述；73% 的文件一条都没有 |

**这些方案全部被否决，但理由不止"违反纪律"**——它们**实测也几乎无效**。唯一看起来强的"压成目录 0.647"只是目录层面的完整度，文件层信息丢失。

### 一条数据质量教训（因为不再计算统计而不再需要，但记录在案）

未去团块时，`tools/review/build.zig` 及其 4 个 baseline 文件各报 **16 个伙伴**，`_base/lifecycle/disposer.ts` 等 8 个文件各报 **50 个伙伴**——全部来自两个机械提交：`26eaf0cd71 style: format the source trees with oxfmt`、`1ab19190e9 refactor: strip comments from agent-core-v2…`。**一旦开始计算成对统计，就必须处理批量提交生成的完全图**；raw 投影天然免疫。

### 成本实测（本仓库 3973 提交）

```
git log --format='%s'                    0.2s
git log -395 --name-only --format='%H'   0.9s
git log -395 --numstat --format='%H'     2.6s
git log --numstat --format='%H'         13.0s
```

## 需求

**R1 注入必须由系统驱动，不得要求模型主动调用任何工具。**
三层触发全部自动：会话启动、轮次开始、文件进入视野。存在不主动调用工具的模型。

**R2 主通道是文件级条件注入（L3），挂在工具结果尾部。**
Read / Edit / Write 命中某文件时，把该文件的记忆附在工具结果里：自动、条件化、时机正确（见到文件后、编辑前）。

**R3 禁止按 token 或字符数裁剪注入量。**
不同模型分词器不同、计费口径不同，token 不是产品级单位。规模只由"取几个提交"这类结构性规则决定。

**R4 注入内容只能是 git 对象的原始投影。**
允许：sha、commit message 原文、author、date、分支名、该提交的路径列表、diff/stat 原文、已提交文件原文。
禁止：计数、频率、排名、共现次数、占比，以及任何祈使句式的结论（"你必须同时改 X"、"通常一起改"）。
每一条注入行都必须能对应到一个 git 对象，能被 `git show` 复核。

**R5 选择规则必须结构性、可复述。**
"取最近 N 个"、"取触碰该路径的提交"、"取最近一次"——规则本身必须能用一句话说清，且不依赖任何统计量。

**R6 L3 的主载荷是该文件最近 3 个提交的原始投影。**
每组含：sha、日期、author、subject 原文、该提交的完整路径列表。不压成目录，不加统计。

**R7 L1（会话启动）只含最近 5 个提交的原始投影。**
不再包含提交约定词汇表与共变不变量——那些是统计量。

**R8 唯一的规模抑制：单组提交触碰文件数 > 25 时不列路径。**
只输出 sha、日期、author、subject。**连文件数都不写**（那也是计数）。这类提交是批量操作，路径列表没有信息量。

**R9 L2 只在能从最近一条用户消息抽出文件路径时触发**，抽不到跳过，不做猜测式注入。取前 2 个路径，各带最近 2 个提交。

**R10 去重：文件级 + 提交级。**
每文件每会话只注入一次；同一提交每会话只铺开一次，后续引用它的文件只输出 `see commit <sha> above`。

**R11 取数只允许窗口扫描，缓存命中时零 git 进程。**
只跑 `rev-parse HEAD`、`log -N --format=...`、`log -N --name-only`。禁止在启动/工具路径跑全历史 `--numstat`。索引按 HEAD 缓存。

**R12 失败必须降级且留痕，不得阻塞工具调用。**
非 git 仓库 / git 缺失 / 超时 → 不注入（`log.debug`/`log.warn`）。索引损坏 → 丢弃重算。

**R13 注入文本是 C2 模型资产：英文、不翻译、不加 locale key。**

**R14 不改 `knowledge` 库 schema；`Memory` 的 markdown 库保留，但改由 git 管理。**

**R15 新增实验性 flag `git_memory`，默认关闭。**
flag 关闭时三层都不注入、不 spawn 进程、工具输出与今天逐字相同。

### 第二部分：写入记忆的 git 化

**R16 `Memory` 的 markdown 库改由 git 管理，每次写入一次提交。**
`memoryBaseDir`（`memoryStore.ts:48`）成为 git 仓库；author 固定 `kimi-code memory <memory@local>`；message 体例 `remember:` / `update:` / `forget:`，**不出现 agent 身份**（`CONVENTIONS.md:15`）。

**R17 提交失败不得掩盖写入结果。**
文件写入成功但提交失败时，返回结果必须写明"已写入、未提交"及原因并 `log.warn`；不得因提交失败而回滚文件，也不得静默（`CONVENTIONS.md:196`）。

**R18 写入必须可回滚：新增 `log` 与 `revert` 两个 action。**
`revert` 只在该仓库内执行 `git revert --no-edit`，不触碰其他路径。

**R19 每条记忆必须声明适用范围 `applies_to`，否则不进入文件级注入。**
无 `applies_to` 的条目归入 L1，规模由条数控制，不按 token。

**R20 写入记忆与派生记忆共用同一注入位置与去重规则。**
同一个 `<file-memory>` 块内的 `<memory>` 子段；同一 sha 每会话只注入一次。

**R21 注入的每条写入记忆必须携带 `sha` 与 `date`，使审计闭环。**
人可以 `git show` 复核、`git revert` 撤销。

**R22 并发写入必须串行化提交。**
仓库目录加独占锁；持锁超时则跳过提交并报告，不得产生半成品提交。

**R23 记忆内容必须逐字来自已提交对象；agent 不得生成新的事实性内容。**
- **人可以自由写记忆**——那是人的内容，不是 AI 生成。
- **agent 通过 `Memory` 工具写入时，只能写"引用型"条目**：指向一个已存在的 git 对象（sha）+ 原文引用。不得写自由散文式的结论或判断。
- 这条是"禁止用 AI 生成"在写入侧的直接推论，也是本 spec 里唯一需要解释的地方：R4 要求注入内容是 git 对象的原始投影，而自由散文的记忆条目不是 git 对象。

**R24 `note` 字段存 git 记不住的部分。**
`intent`（为什么做，进 commit message）与 `note`（**否决的备选方案、取舍、当时的约束**）分开。`note` 是负知识的一等载体——git 记不住"我们否决了 passport.js，因为太有主张"。由人填写。

**R25 写入记忆用"瘦索引"形态，正文不复制进索引。**
索引项 = `{ sha, intent, note, applies_to, date }`；内容从 git 重建。避免两份真相。

## 决策记录

| # | 决策 | 理由 |
| --- | --- | --- |
| D1 | 自动注入引擎，不是摘要也不是工具 | 摘要在任何预算下召回趋零；工具依赖模型主动调用（R1 排除） |
| D2 | 主通道挂在工具结果上 | 自动、条件化、时机正确 |
| D3 | **注入只写原始投影，不写任何统计描述** | 让 AI 参与注入就有不稳定性，再强的模型也会幻觉；且原始投影可被 `git show` 复核（R4） |
| D4 | 不按 token 裁剪 | 目标函数错位；且 token 随模型而变 |
| D5 | 优先召回而非精度 | 漏掉导致失败回环，成本比多给路径高 12–35 倍 |
| D6 | **完全不做统计**：不成对、不去团块、不算权重 | 统计量违反 R4；且实测这些统计量本身几乎无效（0.006–0.123） |
| D7 | 载荷用最近 3 个提交的原始投影 | 它就是召回 0.463 的那个形态；压成目录虽达 0.647 但那是目录层，且是派生描述 |
| D8 | 不做 LLM 摘要 | R4；且成本随历史线性增长、有损 |
| D9 | 不做向量检索 | 无 embeddings 客户端、无向量索引；结构信号已近天花板 |
| D10 | 不改 `knowledge` schema | `sqliteKnowledge.ts:48` 有 CHECK 约束且无迁移机制 |
| D11 | 写入记忆用**独立** git 仓库，不用用户工作区仓库 | 不污染用户仓库；`memoryStore` 已在 `~/.kimi-code/memory`，改动面最小 |
| D12 | 派生的仓库知识不套第二层 git | 源头就是 git，sha 已提供审计与回滚；再存一份只会漂移 |
| D13 | 写入记忆必须声明 `applies_to` | 否则无法自动注入，只能当文档 |
| D14 | 不把"提升召回"当作本模块的卖点 | 实测召回天花板 0.639；git 记忆的价值在**可控性**：可审计、可回滚、可合并 |
| D15 | **注入路径禁止任何 LLM**（检索 agent、摘要器、去重/综合 agent 一律排除） | 生成内容会漂移、会幻觉。DiffMem 的检索 agent 路线因此被否决 |
| D16 | 负知识（`note`）升为一等字段 | GCC 用 `note` 专存 git 记不住的东西，并提供 `--decisions` 单独检索——这一类知识此前被我错误地排除 |
| D17 | 预算单位若需要，用**字符数**而非 token 数 | 不同模型分词与计费不同，token 不是产品级单位 |
| D18 | agent 只能写"引用型"记忆，不能写自由散文 | R23："禁止用 AI 生成"在写入侧的推论；人写的内容不受限 |

## 排除范围

- **不做任何统计型记忆**：共现、频率、排名、占比、约定词汇表、模块划分（全部实测无效且违反 R4）。
- **不做向量检索**（D9）。
- **不做 LLM 摘要、不做检索 agent**（D8、D15）。
- **不做建模主动查询的工具作为主通道**（R1）。
- **不做"拆分提交成更小单元"**：已实测四种拆法全部输给"单元 = 原始提交"。
- **不读 forge API**（PR 描述、review 讨论）——需要凭据与网络，另开 spec。
- **不改 `<git-context>` 现有字段**、**不改 `promptPrefix` 机制**。
- **不把 memory 仓库推到远端**：只提供能力，用户自行配 remote。
